# 三团真实交汇补验契约

所属`WS-MAINT-20260920-001`，legion40，B的隔离模拟准备；不是正式实现。正式legion39事件排序正在完整门和自然长局复验，保持其运行源码冻结。

目标：补齐当前仅有双团通行的缺口。在真实`jungle_upper_major`（8192,9216）四向连接处，用三支真实军团从不同方向进入、分批汇入通向upper_rear的320窄路。使用真实MapDefinition/LogicGrid，12和60士兵另加将领、最多12实体一批、三列48间距、批间96净空。全部退出单位持续占位，不能删除腾空间；将领和实际突击/装甲护卫同批。

正常流量、相同输入重放、180度镜像、已入路后临时手控停止及恢复、永久手控停止、实际出口占位拒绝分别验证。占用路口的批次尾部实际清出才释放，不以队首通过或计时到期放行；路口释放不代表整条后续窄路方向清空。通过上游等待位置与真实出口槽容量控制准入，记录排队、放行、尾清、退出时刻及实际位置。

每tick检查速度、中心路径、单位间最小24中心距、批次大小、护卫同批、实际出口承诺不重叠、玩家停止不被移动；不允许用瞬移完成转弯。请求与移动使用稳定ID次序。镜像和重放比较逐tick轨迹摘要及任务结果，预期受阻不记成功通行。

本实验是三团同向合流，**不能代替三出口互锁循环、任意平台自动容量搜索或敌方追击/包围验证**；没有新增平台/道路或赋予隐藏情报。本轮若发现几何/调度缺陷，保留失败后修正并重跑对应输入。只有实际执行结果完整才记PASS；未运行项为NOT_RUN。HUMAN和像素NOT_RUN，不作性能结论。

## 失败及原因

1. smoke01类型推断错误，未进入模拟；修正typed批次数组后才得到有效smoke02。
2. smoke02在急弯将左右法向线性混合，三列挤向同一区域，首批卡住；miter交点版本smoke03仍有局部自交。原始源码与失败JSON/日志保留。
3. 圆弧转弯使列保持不同半径，逐人速度预算继续约束弧上步进；smoke04仍超时，因为三个入口弧长不同，却用不同的路径进度数字描述同一个下游位置。统一出口段的实际距离后smoke05的12人合流通过。
4. matrix01的满编normal再次超时，随即终止该矩阵（66923退出1，确认仅停止测试PID43440/36352）。full-smoke01复现193.0秒起全体静止：容量搜索跳过前批临时占位，随后又把腾出的较前方槽分给后批，造成无法超越的队列。
5. 改为按进入次序从远到近连续预约、目标槽暂被前批经过就等待，不让后批在前批前方落位。full-smoke02的满编输入通过；最终matrix02完整16场和replay01的8对均通过。所有已有真实占位与承诺一起检查，未通过降低24碰撞下限或240护将上限解决。

期间另一个simple夹具不能满足真实容量/到位契约，已弃用为`artifacts/legion40/abandoned-simple.gd.txt`，其解析失败和16场失败均不计入有效验收，也不能当方案通过。有效入口仅`tests/tools/legion40_junction_lab.gd`及`legion40_junction_replay.gd`。
