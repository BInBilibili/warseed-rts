# 中间成长阶段的撤退阵位单因素验证

工作项 `WS-MAINT-20260920-001`，legion46，为新版阵型的隔离模拟补验。legion45 正式移动修复的完整门与自然双局验证均已结束，结论见[本地护卫验证报告](LEGION_CORE_COHESION_FIX_20260924.md)，完整B仍需返工。697 个运行文件保持冻结；本实验仅新增测试、证据和文档。

问题：legion44 中所有 24/48 人编制在近距离持续追击下失去将领，但将领到最近真实核心均未超 240。要检验初始站位是否贡献了失败，不能直接提高将领生命或混改断后规则。

固定输入：五团 × 24/48 名士兵 × 立即/延迟30tick撤退 × 中心镜像；同3016撤离距离、固定600tick观察、相同敌方云岚编制、192初始接触间隔与合法可见追击、相同战斗系统/数值/道路/速度/队列/净空。

只改变己方将领的初始阵位，共三种布局：

- control：完整复用legion44初始布局。
- within_batch_exit：将领与原同批靠出口侧最后一位成员交换位置。
- next_batch_exit：将领与靠出口方向下一批第一位成员交换位置。

交换同时重绑实体到既有阵位，其他阵位、批大小、列、间距及敌人完全不变。双方成员总数与编制不变；检查新将领批次仍有至少一名真实核心。交换发生在实验初始化，**不是允许正式游戏瞬移换位**。若某候选失去护卫或违反真实几何，判为夹具/候选失败，不跳过样本。

120场正式矩阵；其中40场control逐项回查legion44对应原始结果，镜像60对比较规范化轨迹与战斗结果。先跑少量smoke，最后另进程重放候选布局的五团×24/48×立即撤共20场。断言数与场数分别统计，失败保留。原有军团清守军保留率门槛不变，强追击不是低损清点验收。

主要观察为固定600tick将领存活、最终脱离、残存士兵、首次失将/脱离时刻、敌方实际开火与运动；同时记录初始将领批次/阵位变化与同批护卫数。只证明这个受控初始布局的差异；即使候选改善，也不证明从交战阵型真实转换过去可行、不替代动态截路/包围/接应、完整交通或正式B/C/D。证据 `SIMULATED_PROTOTYPE`，HUMAN/原生像素 `NOT_RUN`。

## 完成结果

矩阵52038实际退出0，120场；独立重放78759实际退出0，20场。60对镜像的规范化轨迹和全部结果一致，40条control与legion44原记录逐字段一致，20场新进程重放与矩阵完全一致。矩阵124589728次执行检查无失败；这不是战斗场数。独立回执[`verification.json`](../artifacts/legion46/verification.json)，命令`python artifacts/legion46/verify_positions.py`。697个正式运行文件相对legion45冻结未改变。

## 对设计的约束

1. 撤退阵位应单独按撤出方向分配真实护卫和将领位置，不能只沿用进攻中间槽或将全团转向。后置一批保留为待验证候选，尚未正式接入。
2. 必须验证从原阵位实际走到候选位的耗时、穿行净空、护卫交接及途中受火；本实验初始交换不提供这些保证。尤其24人候选已经是最后一批，不能再无限后置而忽略尾队风险。
3. 白九阳48人与林墨延迟撤需要优先检验提前风险退出、断后/炮火掩护和友军接应；固定调高将领血量无法替代这些行为验证。
4. 验收继续分别记录保将、残存士兵、全员到位、脱离接触与后续受威胁状态。原白九阳低损清点门槛保持，当前高压撤退样本不用于认证该任务。
