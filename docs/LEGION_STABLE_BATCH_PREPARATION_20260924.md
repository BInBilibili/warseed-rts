# 稳定身份与批次准备契约

所属`WS-MAINT-20260920-001`，legion42。上一轮legion41完成有效追击证据，本轮继续完整A–D目标；自然55194仍运行，正式687文件保持legion39冻结。仅准备不被游戏加载的typed规划组件与测试，不能把准备组件称为B完成。

目标：将成长身份槽、当前实体和通行阵位分离，消除死亡/补员/接管时全团按存活实体ID重新排号的风险。依赖第二版第6、7.2、7.7节及legion41保护批次对照。规划器只接收己方CommanderSnapshot、己方UnitSnapshot和允许自动执行的卡ID，不读取敌军或世界。调用方仍须执行正式权限/归队/导航/安全复验。

初次编组或在真实安全成阵点获准重编时：对当前可调度成员均衡分为最多12实体一批，将领放在靠撤出侧的中间批次，同批至少1名真实突击/装甲；含炮批次要求至少2名真实护卫，缺员时如实报告不足、不复制护卫。白九阳首批最多先安排2名侦察，其余参与混合组。三列48间距、相邻批包络96净空；坐标是路线局部参考，不代表地图位置合法或已经到位。

在通行或战斗中沿用上一批次映射：死亡产生空槽，原身份补亡后回到同一授权槽；归队未完成、回营或玩家接管成员退出当前推进分母，身份和旧阵位仍保留。新解锁身份暂列后侧待接入，只有获得安全重编条件才重分批，不把旧成员挤位，也不让待接入新兵拖停当前军团。是否确有安全重编空间由后续权威执行器验证，纯规划器的显式输入不构成安全证明。

输出保存typed成员/批次/原因与深拷贝。护卫不足、将领不可用、输入身份不一致必须显式返回；护卫不足不能阻止上层紧急撤退/就地自卫。组件本身不移动、不转向、不取消原任务、不生成玩家单兵操作、不改成长费用。四态空间编组、局部补位、实际行走、交通预约、UI和命令接线仍是完整B后续要求。

验收：双方五将从12到60每一步的唯一身份、精确人数、批次容量/均衡、同批护卫、三列参考净空、镜像/输入顺序/实体编号变化不改变身份布局；战损、原槽补亡、归队、手控、无核心及新人成长不引发原批次重排；旧快照不能被新计划改写；真实双方开局快照可消费。使用Godot headless，证据`artifacts/legion42/`；另核对legion39冻结、日志/退出码、文档和diff。没有正式权威行为变更，不重复完整发布门；HUMAN/像素NOT_RUN，v4不变。
