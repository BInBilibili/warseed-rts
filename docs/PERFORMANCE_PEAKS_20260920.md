# perf28 性能与峰值优化

同一工作项WS-MAINT-20260920-001，续作perf27。用户要求应用所有优化并尽量解决尖峰。证据全部SIMULATED，仅无窗口；10Hz、610实体上限、当前单导弹规则、合法知识/快照值隔离、事件顺序、v4和全部视觉内容保持。

## 实施范围

- 报告仅解析实际消费的事件；敌人合法观察历史按完整字段变化更新字典，保持全部历史及输出顺序。减少每事件枚举数组创建。
- 常驻模拟worker在完整tick后，以独占projector准备合法态势/命令态势。通过完成信号交付只读typed视图；宿主按快照对象与定义身份缓存最多3份，报告仍按原10tick采样，HUD仍按原阶段读取。消除主线程重复投影；同步/legacy保留原语义。命令仍在tick边界校验，没有改成提前接受。
- 选择修剪按快照索引，避免多选时每帧逐个线性查询全部单位；军团活动指示使用敌人空间桶，最后仍执行原距离判定。
- C#正式批绘内核与容量预留默认启用，GDScript回退保留。Godot保留精确三角函数、Vector2 recoil及AABB；C#复用每组数组填充两个16-float缓冲。容量按组增长、visible_instance_count限制有效前缀，全部单位/动画/弹道不变。正式程序集仅编译指定源文件，避免编入artifacts副本。
- 事件字段查找不再分割整串；固定枪口多边形复用。原导航、视野、快照和报告缓存优化继续保留。
- Compatibility渲染器保留。GPU光栅、驱动/着色器峰值、渲染器切换、分辨率缩放和画质降级没有可接受的等价实渲证据，未启用。不能把互斥渲染器或降画质开关都称为“优化已应用”。正式C#实现替代此前隔离原型，不再维护第二套C++实现。

## 峰值证据与失败修复

perf28-trace-before把逐帧时间关联到带时间戳的区段：最大48.509ms帧内，report.situation为21.542ms；第二峰42.640ms内report.observe为28.442ms。trace为可选诊断，默认关闭，模拟决策不读取它。此前perf27的52ms host.publish包含报告，不能归因于事件发布本身。

报告/投影优化后首轮P50/P95/max19.063/28.310/48.509→15.614/26.356/35.529ms，均11290次发射。这是诊断单轮，不代替最终三轮对照。加入完整内核的中间轮16.106/27.436/36.790ms；新trace报告投影查询最多6微秒，观测数据整理仍有15.288ms峰值。

失效试验和已修复问题均保留日志：

1. 首次C#能力检测使用OS feature时当前项目未声明C#，实际走回退；改为ClassDB检查并补正式工程feature，专项明确断言native实例非空。
2. .NET与Godot的sin(PI)末位不同，严格buffer检查失败；保留Godot精确c/s后31710项通过，没有放宽数值断言。早期探针误要求可变绘图缓冲永久不变，该条件不是生产契约，移除后仍逐帧比较有效输出；权威快照隔离继续独立验证。
3. PackedVector2Array不能作为该语法下的const表达式，改静态只读点数组；首轮import失败日志不计通过。
4. 共享HUD入口曾遗漏Legacy卡牌模式判断，审查发现后补回，增加旧模式对照。
5. 初次导出目录缺失；第二次虽退出0却含缺少WARSEED.sln错误，均不计通过。补解决方案后成功携带.NET运行时。
6. Godot导出模板禁用--script和场景路径覆盖，两个旧探针只启动菜单被核对命令行后停止，并非游戏逻辑挂起。增加仅headless+debug+显式--verify-art-kernel的诊断入口；真实EXE验证610实例、C#非回退、缓冲/AABB/reset、worker态势和炮车规格。一次导出退出时出现Android EditorSettings错误，保留日志，最终完整门以其独立最终输出为准。
7. 编辑器脚本类缓存曾缺少新类型，重新导入后恢复；未停止用户编辑器。
8. 首轮完整门的整合测试把分配容量当作有效实例数，并检查了预留尾部的变换。改为检查visible_instance_count恰等于已知单位数、在分配范围内且所有可见变换比例不变；未减少有效单位数/画面断言，300帧容量专项仍逐项比较有效前缀。首轮失败日志归档perf28-release01-failed.log及perf28-supervisor01-failed.log，重跑完整门。

C#局部对照并非原型的7.5倍：300帧动态分组混合冷启动中，GDS基线P95为1.331ms、native精确容量1.226ms、native预留1.289ms；总时间分别219.270/205.239/254.981ms，预留路径包含45.969ms首次高峰（未据此断言成因为JIT）。跨语言参数和结果转换仍分配内存，GPU上传也未测，因此必须保留最终端到端尾延迟结果，不宣称消除GC或容量方案必然更快。程序集和自带.NET运行时增加约79MB未压缩文件，独立包会完整携带。
